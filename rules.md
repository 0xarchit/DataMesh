# Project Rules

Rules for all code, documents, and output in this project. Follow them exactly.

## Code

- No comments. The code speaks for itself. Do not add explanatory comments, section banners, or TODO notes.
- No random or decorative symbols. Plain ASCII only. No emoji, no arrows, no box-drawing characters, no checkmarks, no decorative unicode.
- No em-dashes anywhere. Use a plain hyphen or rewrite the sentence.
- Simplest solution that works. No speculative abstraction, no config for values that never change, no scaffolding for later.
- Reuse what already exists in the project before writing anything new. Check first.
- Prefer the standard library and already-installed dependencies. Do not add a new dependency for what a few lines can do.
- Fewest files possible. Do not create a new file when an existing one fits.
- Do not leave the code in a broken state. If it runs, it stays running.

## Editing

- Do not change structure that was not asked about. Keep existing formatting, headings, order, and layout.
- Change only what the task requires. No opportunistic rewrites.
- When a file has a working structure, preserve it and edit in place.

## Writing and output

- Clear and precise. No filler, no padding, no restating the obvious.
- Plain and human. No AI-slop phrasing, no inflated claims, no sales language.
- No em-dashes, no decorative symbols in prose either.
- Be honest. State what is verified and what is not. Do not overclaim.
- Do not endlessly append to a file. Keep it clean and human-readable, rewrite when it gets messy.

## Scope

- Keep the scope as originally stated. Do not silently cut it down to make the work easier.
- If something must be reduced, say so and why, do not just drop it.
